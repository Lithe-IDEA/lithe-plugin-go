2.0.0 在「运行/调试配置」里加入 Go 构建和 Go 测试两种运行配置，并把 gopls 的索引排除改为由清单声明。这个版本需要还没有发布的新版桌面端，所以是预发布版本。

功能：
- Go 构建：点「运行/调试配置」的「+」，选 Go 构建。运行种类可选软件包、文件或目录，执行 `go run`；软件包填导入路径（如 `example.com/app/cmd/server`）或相对路径（如 `./cmd/server`）。“Go 工具实参”放在 `go run` 后面，例如 `-mod=vendor`；程序参数传给程序。
- Go 测试：测试种类可选软件包或目录，执行 `go test`。软件包默认 `./...`；目录会测试它和子目录里的所有软件包；“模式”作为 `-run` 传入，只运行匹配的测试。
- 两种配置都可以存为项目文件（写进 `.lithe/run/plugin/io.github.lithe-idea.go-support.toml`）、允许多个实例，并使用 Lithe 统一的程序参数、工作目录、环境变量和启动前步骤。用的 `go` 和构建窗口相同，构建选项里的 Build Tags 和 Race Detector 也会加进命令。名称、说明和字段有中文翻译。
- 用户排除在索引之外的目录由 Lithe 按清单里的 `indexingExclusions` 写进 gopls 的 `directoryFilters`，不再写死在 Lithe 里。

已知限制：
- 这两种配置还不能调试，调试请用「调试」窗口的 Go (Delve)。
- 插件字段排在工作目录和环境变量前面，运行种类和测试种类显示为分段按钮；Go 测试的目录不会默认填项目根目录，名称不会自动生成。
- 还没有输出目录、构建后运行、模拟终端、重定向输入、以 sudo 运行、模块、测试框架和使用所有自定义构建标记这些选项。

验证：
- 在 macOS 上用包含 1lck/Lithe-IDEA#2148 的桌面端跑宿主端到端测试：在对话框里新建 Go 构建和 Go 测试，运行结果和保存的配置都符合预期，插件安装目录不被写入。
- `scripts/test.mjs` 用真实的 go 运行两种配置拼出的命令，覆盖软件包、文件、目录的 Go 构建和软件包、目录、模式过滤的 Go 测试；CI 在 macOS、Windows x64 和 Windows ARM64 上运行它。
- 还没有在 Lithe 里手工验收，状态见 `docs/feature-matrix.md`。

权限：不变。

兼容性：
- 需要支持插件声明运行配置类型的桌面端（1lck/Lithe-IDEA#2148，固定了 Lithe-core-rust#94 的 Core）。已发布的桌面端 0.8.5 及更早版本都不包含它，会拒绝安装 2.0.0；请继续使用 1.0.1。
- `indexingExclusions` 需要 Lithe-core-rust#68，桌面端 0.8.5 已包含。

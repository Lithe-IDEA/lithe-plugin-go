1.4.0 让 Go 设置页的预览跟着设置窗口的宽度重新排版，不再随窗口放大或被裁掉。

功能：
- 「设置 › 语言 › Go」的四张预览卡片按窗口实际宽度排列：放得下两张时两张一行，窄了一张一行；卡片随窗口变宽，里面的文字和代码保持 Lithe 自己的字号。
- 「构建工具 › Go」的查找顺序图跟着窗口变宽，设置的 go 路径较长时能显示更多。
- 拖动窗口改变宽度后，宽度稳定下来，预览就按新宽度重新排版。
- 深色外观下，点亮的标签（“开”“一行”等）文字改用正文颜色，不再是蓝底上的蓝字，看得清楚。

已知限制：
- 跟随窗口宽度需要包含 1lck/Lithe-IDEA#2191 的桌面端，这个版本还没有发布。桌面端 0.8.7、0.8.8 不告诉插件窗口宽度，预览和 1.3.0 一样按最小的设置窗口排版。
- 需要桌面端 0.8.7 或更新版本（含插件视图 1lck/Lithe-IDEA#2183）。桌面端 0.8.6 不认识 `settingRegions`，安装或更新到这个版本会失败。
- Windows 上代码的字距比 Lithe 自己画的略宽：预览按 SF Mono 的字宽排版代码，选区和波浪线才能对准字符。

验证：
- 后端测试检查两种语言下每个预览在各个宽度都画在视图以内、卡片内容不超出卡片，两张一行只在放得下两张最窄卡片时出现，宿主不给宽度时退回最小窗口的排版。
- 在 macOS 上用 1lck/Lithe-IDEA#2191 的桌面端跑宿主端到端测试：两个预览在中英文下按宿主给的宽度画出、通过 Core 校验，窗口变宽后按新宽度重画，草稿仍然标出，插件安装目录不被写入；原有的构建、调试、运行配置和新建项目测试也都通过。
- 把后端画出的预览放进宿主的无头界面，用设置窗口的浅色和深色配色截图，检查了几种窗口宽度下中英文、默认值和全部开启时的排版。
- Windows 包的后端只在 CI 里构建，还没有在 Windows 版 Lithe 里打开过；状态见 `docs/feature-matrix.md`。

兼容性：
- 发布包按平台分开：`-darwin.zip`（Apple Silicon 和 Intel 通用）、`-windows-x64.zip`、`-windows-arm64.zip`。
- 后端用到的第三方 crate 和许可证见包里的 `THIRD_PARTY_LICENSES.txt`。

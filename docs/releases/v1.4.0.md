1.4.0 是实验版本：一个仓库里有多个 Go 模块时，项目树把每个嵌套模块的目录标成「源代码根目录」。

功能：
- 打开工作区时，插件找出根目录以下各层的 `go.mod`，把每个嵌套模块所在的目录标成「源代码根目录」，项目树里一眼能看出哪些目录是独立模块。
- 根目录本身的模块不标（Lithe 不给工作区根目录加标记）；`vendor`、`testdata` 和以 `.`、`_` 开头的目录里的 `go.mod` 不算，和 go 命令的规则一致。
- 标记只在这次运行里有效，不写进项目文件；关闭项目、停用插件或插件后端停止后标记随之消失。
- 你自己在项目树里设的目录类型、颜色和项目共享的目录规则都优先于插件的标记。

已知限制：
- 需要支持插件目录标记的桌面端（1lck/Lithe-IDEA#2480，固定 Lithe-core-rust#215），还没有桌面端版本包含它。较早的桌面端不认识新增的权限，会拒绝安装 1.4.0，可继续留在 1.3.2；这个版本作为预发布版本发布，不进 Lithe Store。
- 只在打开或关闭项目时查找 `go.mod`。项目打开后新建、删除的模块，要等下次打开或关闭项目才会更新标记。
- 只处理本地、只有一个根目录的工作区；远程工作区和多根工作区不标。
- 宿主的文件搜索最多返回 200 个结果，超过的 `go.mod` 不标，并在插件日志里记一条警告。
- 新增了打开工作区就启动的激活事件，打开任何工作区（包括不是 Go 的）都会启动插件的小后端。

验证：
- 在 macOS 上用 1lck/Lithe-IDEA#2480 的桌面端跑宿主端到端测试 `TestOfficialGoPluginMarksNestedModuleDirectories`：后端随工作区启动，经宿主的文件搜索找到 `go.mod`，标出 `tools` 和 `services/api`，Core 把标记解析成项目树里的「源代码根目录」，`vendor`、`testdata`、`_old` 和只有 `go.mod.bak` 的目录不标，插件安装目录不被写入。同一次运行里原有的构建、调试、运行配置、设置预览和新建项目测试也都通过；需要另配 Go 1.22.12 和两个 Delve 版本的 `TestOfficialGoPluginDebugsWithConfiguredDelve` 这次没有跑。
- 本地运行后端 `cargo test --workspace --locked`（31 项通过）、macOS 通用二进制打包与 `scripts/package/*.test.mjs`（3 项通过）、`scripts/test.mjs`（10 项通过，gopls 和 dlv 的安装检查按 `LITHE_TEST_INSTALL=0` 跳过）。
- 还没有在真实窗口里手工验收，Windows 版 Lithe 里也没有运行过；状态见 `docs/feature-matrix.md`。

权限：新增 `workspace.metadata`（读取打开的工作区）、`workspace.search`（按文件名查找 `go.mod`）和 `workspace.directoryMarks`（标记目录）；激活事件新增 `onWorkspaceOpen`。

兼容性：
- 发布包按平台分开：`-darwin.zip`（Apple Silicon 和 Intel 通用）、`-windows-x64.zip`、`-windows-arm64.zip`。
- 后端用到的第三方 crate 和许可证见包里的 `THIRD_PARTY_LICENSES.txt`。

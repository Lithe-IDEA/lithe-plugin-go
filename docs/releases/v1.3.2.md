1.3.2 新增全局 **Delve executable**（中文界面：**Delve 程序**）设置，允许选择与项目 Go 版本兼容的本机 Delve（`dlv`）可执行文件进行调试（[#26](https://github.com/Lithe-IDEA/lithe-plugin-go/pull/26)、[#27](https://github.com/Lithe-IDEA/lithe-plugin-go/pull/27)）。

修复与改进：
- 在「设置 → 插件 → Go Support → 设置」的「Go 工具链」分组新增 **Delve executable** 文件设置，从下次启动调试开始生效：
  - 留空时保持原有自动查找顺序：先查找 `PATH` 中的 `dlv`，再查找插件记录的安装目录。
  - 显式指定本机兼容的 `dlv` 可执行文件后，调试会话优先使用该路径启动 Delve；Delve 自身的 Go 版本检查保持开启。
  - 显式路径不适用于本机、文件不存在或无法执行时，桌面宿主会在调试面板提示前往插件设置选择有效的本地可执行文件。
- 补全中文界面翻译（`l10n/zh-Hans.json`），更新调试说明与功能矩阵，并新增宿主端到端测试 `TestOfficialGoPluginDebugsWithConfiguredDelve`（固定宿主至包含 1lck/Lithe-IDEA#2464 的版本）。

已知限制：
- 需要 Lithe 桌面端 `0.8.20` 或更新版本（支持 `debugAdapters[].launch.executableSetting`，对应 1lck/Lithe-IDEA#2464 及固定了 Lithe-core-rust#207 的 #2468）。更早的桌面端不认识该清单字段，会拒绝安装或更新到 1.3.2，可继续留在 1.3.1。
- Delve 本身仍不支持 Windows ARM64，该平台没有调试功能。

验证：
- 在 Linux x86_64 宿主端到端测试中验证 `TestOfficialGoPluginDebugsWithConfiguredDelve`：使用 Go 1.22.12 与 `PATH` 中 Delve 1.27.2 触发预期的 Go 版本不兼容错误后，通过设置保存 Delve 1.23.1 的绝对路径，成功命中断点、读取局部变量并完成退出，插件安装目录保持不变（[#26](https://github.com/Lithe-IDEA/lithe-plugin-go/pull/26)、[#27](https://github.com/Lithe-IDEA/lithe-plugin-go/pull/27)）。
- 本地发布前运行后端 `cargo test --workspace --locked`（24 项通过）、macOS 通用二进制打包与 `scripts/package/*.test.mjs`（3 项通过）、`scripts/test.mjs`（14 项通过）。
- Windows 包由 CI 构建并跑 `scripts/test.mjs`（Windows x64 与 Windows ARM64 原生 runner）；macOS 与 Windows 桌面端完整手工验收状态见 `docs/feature-matrix.md`。

兼容性：
- 发布包按平台分开：`-darwin.zip`（Apple Silicon 和 Intel 通用）、`-windows-x64.zip`、`-windows-arm64.zip`。
- 后端用到的第三方 crate 和许可证见包里的 `THIRD_PARTY_LICENSES.txt`。
